# 病気博物館（Disease Museum）

国試レベルの医学を「遊んで覚える」ための、ポップでインタラクティブなWeb教材。臓器ごとの「ホール」に、ゲーム型の「展示」が並ぶ博物館という世界観。

オーナー：太田（京大医学部6年）。医学内容の最終レビューはオーナーが行う。

## 最優先の価値（判断に迷ったらこの順）

1. 楽しさ、ポップさ、触って動くこと
2. 国試で問われる判断（鑑別、重症度、治療選択）をゲームの操作そのものにすること
3. 医学的な正確さ（後からレビューで直す前提。ただし下書きであることを必ずデータに残す）

「知識を1つ表示する仕掛け」ではなく「判断を迫るゲーム」にする。正解が1つに決まらない場面では、複数正解を許すか解説で補う。

## 現状

- `reference/kantansui_hall_v2.html` が完成済みの試作（肝胆膵ホール ver.2、単一HTML、約110KB）。見た目、手触り、ゲームバランスの基準はすべてここ。
- 公開中の試作：https://claude.ai/artifact/Mt9CXYjDQjDXep7RaXwwTx
- 次の仕事は、この試作から「エンジン（展示の型＋共通機能）」と「ホールのデータ」を分離し、同じ品質で他のホールを量産できる形にすること。詳細は `docs/ROADMAP.md`。

## 技術方針

- Vite + TypeScript（フレームワークなし、素のDOM）。展示の型ごとに1モジュール。
- ビルド成果物は2種類。
  - 通常ビルド：ホールごとのページを持つ静的サイト。
  - 単一ファイルビルド：ホール1つを1枚のHTMLにまとめる（vite-plugin-singlefile など）。Claudeのartifactとして公開するため、外部ファイルを参照しない。
- 外部から読み込めるのはGoogle Fontsと、cdnjs などのスクリプトのみと想定する。画像は使わず、図はすべてインラインSVGかCSSで描く。
- 医学データはホールごとに `src/halls/<hall>/data.ts` に置き、zodで型と値を検証する（ビルド時に失敗させる）。
- 保存は localStorage。読み書きは必ず try/catch で包み、空でも壊れないこと。

## デザインシステム（試作から抽出。勝手に変えない）

- フォント：見出し「Dela Gothic One」、本文「M PLUS Rounded 1c」（500/800）。
- 色トークン：tomato #FF5A36、sun #FFC933、mint #22C1A0、cobalt #3D5AFE、pink #FF7AB6、bile #8BD450、liver #C8453B、ink #1C1537、背景 #F5EFFF（ダーク時 #17122E、カード #241C47）。
- 部品の質感：3px の ink 枠線、角丸 14〜22px、4px 4px 0 のベタ影、押すと影が消えて沈むボタン、背景にドット柄。
- 臓器キャラ：臓器に目（まばたき）と口とほっぺ。
- 効果音はWeb Audioの短いビープで作り、右上のボタンで消せる。紙吹雪はcanvas。
- 必須の配慮：モバイル390px幅で横スクロールが出ないこと、`prefers-reduced-motion`、ダークモード、44px以上のタップ領域、`viewport-fit=cover` とセーフエリアの余白。

## 医学コンテンツのルール

- すべての問題・症例・解説データに `review`（"draft" | "reviewed"）と `sources`（出典の文字列配列）を持たせる。新規作成時は必ず "draft"。
- ガイドラインの閾値や分類（TG18、膵炎の予後因子など）を記憶だけで書かない。確認できなかった値は `// TODO(review)` を付けて、ROADMAPの要レビュー一覧に追記する。
- 確率やスコアを演出として手で決めた場合（黄疸ラボの確率バーなど）は、画面に「イメージ」と明記する。
- 実在の患者情報や画像は使わない。症例はすべて架空。

## 作業の進め方

- 1セッション1目標。ROADMAPのフェーズ順に進め、終わったらチェックを付ける。
- 展示を移植・新規作成したら、Playwrightで390×844と1280×900のスクリーンショットを撮り、目視で確認してから完了とする（`npm run shots`）。
- 既存ホールの挙動を変える変更は、試作と並べて差分を確認する。
- 迷ったら作り込む前にオーナーに聞く。特にゲームの勝敗条件やバランスは、オーナーが遊んだ感想で調整してきた経緯がある（ガチャの天井など。`docs/SPEC.md` 参照）。

## コマンド（Phase 0 で整備する）

- `npm run dev`：開発サーバー
- `npm run build`：静的サイト
- `npm run build:single -- --hall=kantansui`：単一HTML
- `npm run check`：型チェック＋データ検証
- `npm run shots`：全展示のスクリーンショット
